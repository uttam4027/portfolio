PD Smart Assistant

Ask a product-guideline question in plain language and get the answer with its source document.

Built for
Product Development
Type
RAG chatbot

Problem

Product Development teams opened several guideline workbooks by hand to find one parameter or instruction. Every lookup meant searching through documents.

What I built

A chatbot that indexes the company's guideline documents. Users ask in natural language. It answers from the matching guidelines and shows which document the answer came from.

Result

Teams get the relevant guideline from one question instead of manual searching. Only the relevant passages go to the model, not the whole dataset, so token use stays low.

Features and stack
  • Excel guideline processing, chunking and embeddings
  • Vector search in Qdrant with source references on every answer
  • Customer-to-group matching for relevant guideline retrieval
  • Chat history and user login
  • Admin panel and guideline re-indexing
  • Incremental indexing of new and updated documents
  • Token-efficient retrieval instead of sending the full dataset

StackPython, Flask, LlamaIndex, OpenAI, OpenAI embeddings, Qdrant, Pandas, Excel, SQLite

Newsletter Product Research Agent

Newsletters in, structured product research out, with no product-by-product browsing.

Built for
Market Intelligence
Type
AI agent

Problem

The Market Intelligence team opened newsletters one by one, researched each product and compiled the report by hand. It was repetitive and slow.

What I built

An agent that scans a dedicated Outlook folder, pulls out product links, finds the products that are new, visits their pages and collects structured details. An LLM fills in what the page does not say.

Features and stack

  • Automated research on each product page
  • New product identification and deduplication
  • Product attribute extraction with LLM enrichment for missing information
  • Automated scheduling and SQLite storage
  • Excel and CSV reports
  • Dashboard for monitoring runs, products and errors

Jewellery Image Similarity Search

Upload a photo and see which existing SKUs look like it.

Built for
Product research
Type
Computer vision

Problem

Product researchers had to check by eye whether a newly launched design already existed as a SKU, searching a catalogue of hundreds of thousands of images.

What I built

A search tool where the user uploads a jewellery image and gets visually similar SKUs from the catalogue, ranked by similarity score, with an optional metal filter.

Result

Researchers find existing designs that resemble a new one in a single search, which helps avoid duplicate development.

It suggests candidates. It is not an exact-match system, so the research team confirms the final match.

Features and stack
  • Image-to-image similarity search
  • Image preprocessing and cropping
  • DINOv2-based visual embeddings
  • Multi-view image analysis for shape and design detail
  • Shape fingerprint for structural matching
  • SKU-level result grouping, similarity scoring and ranking
  • Optional metal filter

StackPython, Streamlit, PyTorch, DINOv2, Qdrant, NumPy, Pandas, PIL, OpenCV

GST Compliance Document Automation

One to two weeks of manual paperwork became about 10 to 20 minutes, once the data is prepared.

Built for
Finance
Type
Automation

Problem

GST document processing was done by hand. Invoice and ICE Gate PDFs had to be checked, merged, scanned and shrunk to fit the portal's upload limit. For large volumes it took 1–2 weeks and several people.

What I built

An end-to-end tool. It validates the Excel data, finds the Invoice and ICE Gate PDFs, merges them in sequence, compresses them and creates upload-ready batches.

Result

About 10–20 minutes for prepared data, run by one person. Missing files and errors are listed in a verification report before processing starts.

Features and stack
  • Excel-based document validation
  • Automatic Invoice and ICE Gate file matching
  • Missing-file and error identification
  • Sequential PDF merging
  • Smart PDF compression with DPI optimisation
  • Automatic batching within the 5 MB limit
  • Pre-processing verification report, processing logs and batch dashboard
  • Output validation and status tracking

StackPython, Flask, PyMuPDF, Pandas, OpenPyXL, Pillow, OpenCV, SQLite, HTML, CSS, JavaScript

Demand Planning and Inventory Management

SKU classification, weekly forecasts and accuracy scoring in one workflow.

Built for
Supply Chain
Type
Forecasting

Problem

The Supply Chain team needed a structured way to study historical demand, classify SKUs and choose forecasting approaches. Doing it by hand slowed down demand planning and inventory decisions.

What I built

Working with the Supply Chain and Development teams, I turned demand-planning concepts into an automated forecasting and analytics system built around SKU history, frequency and variability.

Result

One workflow shows demand patterns, weekly forecasts, seasonality and forecast accuracy (WAPE and WMAPE) to support inventory planning.

Methods compared: SARIMA, Holt-Winters, XGBoost, ETS, SES, Croston, TSB, linear regression and moving average. The workflow in use applies logic-based moving-average forecasting to sparse-demand cases.

Features and stack
  • Historical sales and weekly demand analysis
  • SKU history, frequency and variability classification
  • Demand patterns FM, MM, SM, New and NM, with CV-based variability
  • Forecast model allocation by demand characteristics
  • Weekly forecasting with TTB, BTT and hybrid workflows
  • Seasonality analysis and forecast confidence scoring
  • Accuracy measurement with WAPE and WMAPE
  • Customer segmentation and customer-level forecasting
  • Forecast caching and reusable outputs

StackPython, Pandas, NumPy, Flask, Excel, forecasting and machine learning techniques
